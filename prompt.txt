============================================================
1. MAIN ARCHITECTURAL IDEA
============================================================

The system uses:

ONE SHARED MAPPO BRAIN
+
MULTIPLE INDEPENDENT VEHICLE AGENTS

The MAPPO policy is shared by all vehicles.

The neural network is NOT separately trained for:

Leader
F1
F2
F3
...

There is one shared actor policy.

However, every vehicle has its own:

- observation
- state
- perception
- decision
- action
- reward

Therefore:

A1 = SharedPolicy(O1)
A2 = SharedPolicy(O2)
A3 = SharedPolicy(O3)

The same brain is used by every vehicle, but different vehicles can produce different actions because their observations are different.

Example:

Leader → ACCELERATE
F1     → CRUISE
F2     → DECELERATE
F3     → DECELERATE

This is REQUIRED.

Do NOT make the entire platoon execute one common action.

============================================================
2. CTDE ARCHITECTURE
============================================================

Use MAPPO with Centralized Training and Decentralized Execution.

TRAINING:

The centralized critic can access the complete global platoon state:

Leader state
+
F1 state
+
F2 state
+
F3 state
+
traffic information
+
weather
+
friction μ
+
waypoints
+
platoon information

The shared actor receives each vehicle's LOCAL observation.

Conceptually:

                    GLOBAL STATE
                         |
                         ↓
               CENTRALIZED CRITIC
                         |
                         ↓
                 MAPPO TRAINING
                         |
              SHARED ACTOR POLICY
                         |
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
         F1             F2             F3
     Local Obs 1    Local Obs 2    Local Obs 3
          ↓              ↓              ↓
       Action 1       Action 2       Action 3


During EXECUTION:

Each vehicle independently provides its local observation to the same shared actor.

The centralized critic is NOT required for execution.

============================================================
3. TRAINING + EXECUTION IN THE SAME CARLA RUN
============================================================

The system must support online reinforcement learning inside the running CARLA simulation.

The overall cycle is:

CARLA simulation
      ↓
Collect state from all vehicles
      ↓
Create individual observations
      ↓
Shared MAPPO actor
      ↓
Independent action for every vehicle
      ↓
Execute actions in CARLA
      ↓
Observe resulting state
      ↓
Calculate individual + collective rewards
      ↓
Store rollout experience
      ↓
MAPPO training update after sufficient experience
      ↓
Updated shared policy
      ↓
Continue simulation

Do NOT perform a completely separate training simulation for each vehicle.

Do NOT train F1, F2, F3 as separate neural networks.

The entire platoon contributes experience to the same shared MAPPO policy.

============================================================
4. VEHICLE ROLES
============================================================

The platoon consists of:

Leader
F1
F2
F3
...
FN

The Leader and Followers are independent agents using the same MAPPO actor.

However, their observations may contain role information.

Example:

ROLE = LEADER
ROLE = FOLLOWER

The Leader's primary objective:

FOLLOW ASSIGNED ROUTE / WAYPOINT
+
OBEY TRAFFIC RULES
+
AVOID COLLISIONS
+
HANDLE OBSTACLES
+
MAINTAIN SAFE OPERATION

Followers' primary objective:

FOLLOW LEADER ROUTE / WAYPOINT TRAJECTORY
+
MAINTAIN SAFE HEADWAY
+
OBEY TRAFFIC RULES
+
AVOID COLLISIONS
+
HANDLE OBSTACLES
+
ADAPT TO WEATHER

IMPORTANT:

FOLLOWING THE LEADER'S ROUTE
does NOT mean
COPYING THE LEADER'S ACTION.

Each follower must independently decide what it should do.

============================================================
5. LEADER WAYPOINT BEHAVIOR
============================================================

The Leader follows the assigned CARLA waypoint/route.

The Leader must NOT randomly change lanes while travelling straight.

If there is no valid reason to change lanes:

KEEP CURRENT LANE.

The Leader may change lane when required by:

- obstacle blocking current lane
- route/waypoint requirement
- valid traffic situation
- safe lane availability

Do not allow random lane switching.

============================================================
6. FOLLOWER WAYPOINT BEHAVIOR
============================================================

Followers should understand the Leader's intended route/waypoint direction.

They should follow the Leader's route while maintaining their own safe position.

A follower must NOT blindly copy:

Leader steering
Leader throttle
Leader brake
Leader lane change

Instead:

Follower observes:
- Leader position
- Leader velocity
- Leader route/waypoint
- vehicle ahead
- traffic
- traffic light
- own state
- weather
- friction

Then the shared MAPPO actor produces an independent tactical action.

============================================================
7. TRAFFIC RULES HAVE HIGH PRIORITY
============================================================

Traffic-law compliance must be treated as a high-priority objective.

Every vehicle must independently consider:

- traffic light
- traffic light state
- distance to traffic light
- lane
- road direction
- waypoint
- surrounding vehicles

The Leader must obey traffic lights.

The Followers must also obey traffic lights and safely react to the Leader.

The model must NOT learn:

"Leader can ignore traffic rules."

Instead:

TRAFFIC RULES
>
PLATOON FORMATION
>
EFFICIENCY

Safety and legal driving take priority over maintaining close formation.

============================================================
8. RED LIGHT BEHAVIOR
============================================================

When the Leader approaches a RED traffic light:

Leader should decelerate and stop.

Followers independently observe the situation and react.

Example:

RED LIGHT
+
Leader slowing
+
F1 safe headway
+
F2 distance to F1
+
F3 distance to F2

Each follower independently chooses its response.

Do NOT force all vehicles to stop at exactly the same time.

For the existing experimental scenario where the Leader remains at the red light for 5 minutes, preserve this behavior as a configurable parameter:

LEADER_RED_WAIT_TIME = 300 seconds

Do not hard-code this value deep inside MAPPO.

The traffic-light logic belongs to the environment/state interface; MAPPO learns the tactical response.

============================================================
9. WEATHER-AWARE SAFE DISTANCE
============================================================

Do NOT use one fixed distance for every weather condition.

Desired headway must depend on driving conditions.

Inputs should include:

- vehicle speed
- relative speed
- weather
- friction coefficient μ

Conceptually:

WEATHER
+
FRICTION μ
+
SPEED
+
RELATIVE SPEED
        ↓
DESIRED SAFE HEADWAY

Clear/high friction:
→ relatively closer safe formation is acceptable.

Rain/lower friction:
→ larger safety margin.

Severe/very low friction:
→ more conservative spacing.

The exact parameters must be configurable.

MAPPO should learn appropriate behavior through reward rather than simply being replaced by a hard-coded rule.

============================================================
10. OBSTACLE AND LANE-CHANGE BEHAVIOR
============================================================

Normal condition:

NO OBSTACLE
+
VALID CURRENT LANE
+
SAFE TRAFFIC
        ↓
STAY IN CURRENT LANE

If an obstacle blocks the current lane:

OBSTACLE DETECTED
        ↓
CHECK CURRENT LANE
        ↓
CHECK POSSIBLE ALTERNATIVE LANES
        ↓
CHECK SAFETY
        ↓
REQUEST LANE CHANGE
        ↓
EXECUTE LANE CHANGE
        ↓
TARGET LANE REACHED
        ↓
RETURN TO NORMAL DRIVING

The system must NOT continuously switch lanes.

Prevent behavior such as:

LEFT → RIGHT → LEFT → RIGHT

A lane-change request must have a controlled state.

Recommended states:

NORMAL_DRIVING
OBSTACLE_DETECTED
CHECK_LANE
LANE_CHANGE_REQUESTED
LANE_CHANGE_IN_PROGRESS
LANE_CHANGE_COMPLETE
RETURN_TO_NORMAL

While a lane change is in progress, do not allow another immediate contradictory lane-change command.

============================================================
12. MAPPO ACTION SPACE
============================================================

MAPPO must produce HIGH-LEVEL TACTICAL ACTIONS.

Do NOT make MAPPO directly output:

- steering angle
- throttle
- brake

Use a tactical action space such as:

0 = CRUISE / MAINTAIN
1 = ACCELERATE
2 = DECELERATE
3 = CHANGE LEFT
4 = CHANGE RIGHT

Each vehicle receives its own action.

Example:

Leader → CRUISE
F1 → DECELERATE
F2 → DECELERATE
F3 → CRUISE

The action vector is:

[
    A_Leader,
    A_F1,
    A_F2,
    A_F3,
    ...
]

============================================================
13. IMPORTANT: ACTION FREQUENCY
============================================================

Do NOT allow the MAPPO actor to rapidly alternate actions every simulation frame.

This can cause vehicle oscillation/wobbling.

Use a configurable tactical decision interval.

Example:

CARLA:
15 Hz simulation

MAPPO:
lower tactical decision frequency

Between decisions, the low-level vehicle controller maintains the selected tactical behavior.

The system must avoid:

ACCELERATE
DECELERATE
ACCELERATE
DECELERATE

every frame.

Use action persistence / minimum action duration where appropriate.

============================================================
14. LOW-LEVEL CONTROL
============================================================

MAPPO is the HIGH-LEVEL decision maker.

A lower-level controller is responsible for physically executing the tactical decision.

Architecture:

MAPPO
  ↓
TACTICAL ACTION
  ↓
LOW-LEVEL CONTROLLER
  ↓
CARLA VEHICLE CONTROL

Do not make MAPPO directly fight with waypoint steering or low-level PID/LQR control.

If Module 1 already contains a low-level controller, integrate with it rather than replacing it.

============================================================
17. REWARD PRIORITY
============================================================

Use strong penalties for dangerous/illegal behavior.

Priority:

1. Collision avoidance
2. Traffic-law compliance
3. Safe headway
4. Stay on valid road/lane
5. Follow waypoint/route
6. Weather adaptation
7. Platoon coordination
8. Efficiency

Example:

COLLISION
→ very large negative reward

RED-LIGHT VIOLATION
→ very large negative reward

UNSAFE LANE CHANGE
→ strong negative reward

UNSAFE HEADWAY
→ negative reward

GOOD WAYPOINT FOLLOWING
→ positive reward

SAFE PLATOON FORMATION
→ positive reward

EFFICIENCY
→ positive reward

Safety must dominate efficiency.

============================================================
18. ONLINE LEARNING LOOP
============================================================

Use the following architecture:

for each simulation step:

    collect global state

    for each vehicle:
        build local observation

    for each vehicle:
        action_i = shared_MAPPO_actor(observation_i)

    execute:
        action_Leader
        action_F1
        action_F2
        action_F3
        ...

    collect next state

    calculate:
        individual rewards
        collective reward

    store experience

    periodically:
        update shared MAPPO actor
        update centralized critic

Continue the simulation using the updated policy.
