# Task: Integrate the Uncertain World + Ghost Drivers + Platoon System

I have two existing CARLA 0.9.9 systems in this project:

1. An **Uncertain World system**

   * Creates the uncertain/driving environment.
   * Contains a **Ghost Driver mechanism**.
   * A vehicle can become "possessed" by a ghost driver.
   * The ghost-driver mechanism must remain functional exactly as it currently works.

2. A **Platoon System**

   * Currently works correctly as a standalone system.
   * It creates/runs the vehicle platoon and its existing control/behavior.
   * Do not rewrite or redesign the platoon logic.

## OBJECTIVE

Create **ONE SINGLE ENTRY POINT** that runs both systems together.

The final execution flow must be:

```
Single Entry Point
        |
        v
Start/Connect to CARLA 0.9.9
        |
        v
Create the Uncertain World
        |
        v
Initialize Ghost Driver Mechanism
        |
        v
Create/Initialize Platoon
        |
        v
Run Platoon inside the SAME uncertain world
        |
        v
Simulation Loop
   |             |
   v             v
Platoon      Uncertainty /
System       Ghost Drivers
   |             |
   +------ SAME CARLA WORLD ------+
                  |
                  v
          Visualization / Logs
```

## VERY IMPORTANT: PRESERVE EXISTING SYSTEMS

Do NOT rewrite the existing uncertainty implementation.

Do NOT rewrite the existing Ghost Driver mechanism.

Do NOT rewrite the existing platoon algorithm/control implementation.

Do NOT change the mathematical behavior of the platoon system.

Do NOT create a second independent CARLA world.

Do NOT launch two separate CARLA simulations.

The goal is INTEGRATION, not redevelopment.

Reuse the existing classes, functions, configuration, parameters and logic wherever possible.

If an existing script already contains initialization or simulation-loop logic, refactor only the minimum necessary amount so that it can be called by the new unified entry point.

Before changing anything, inspect the existing project structure and determine:

* Which file creates/connects to CARLA.
* Which file creates the uncertain world.
* Which file implements the Ghost Driver mechanism.
* Which file creates the platoon.
* Which file contains the platoon simulation loop.
* Which functions/classes can be imported and reused.
* Which parts currently assume they are the only system controlling the CARLA world.

Do not guess the architecture. Inspect the actual code first.

```

ghost_driver = initialize_ghost_driver(uncertain_world)

platoon = initialize_platoon(world)

run_simulation(
    world,
    uncertain_world,
    ghost_driver,
    platoon
)
```

The exact implementation should follow the existing project's architecture rather than blindly using these function names.

* HUD text

# 6. UNIFIED SIMULATION LOOP

Create one master simulation loop.

Do NOT allow the uncertainty system and platoon system to independently call `world.tick()` repeatedly.

There should be ONE authoritative simulation tick.

Conceptually:

```
while simulation_running:

    world.tick()

    # 1. Read current world state
    update_vehicle_states()

    # 2. Update uncertainty / ghost mechanism
    update_uncertainty()

    update_ghost_drivers()

    # 3. Update platoon
    update_platoon()

    # 4. Apply resulting controls
    apply_controls()

    # 5. Update visualization
    update_visualization()

    # 6. Logging
    update_logs()
```

Adapt this to the existing synchronous/asynchronous CARLA configuration.

If the existing system already handles CARLA ticks correctly, preserve that mechanism and integrate the other system into it rather than introducing another tick loop.
