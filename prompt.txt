5. ANTI-WOBBLE ARCHITECTURE
============================================================

This is a HARD REQUIREMENT.

The system must prevent:

ACCELERATE
DECELERATE
ACCELERATE
DECELERATE

every simulation frame.

Do NOT call the MAPPO actor at every CARLA physics tick.

CARLA may run at approximately 15 Hz.

MAPPO tactical decisions must run at a lower configurable frequency.

Use:

TACTICAL_DECISION_INTERVAL

Default:

1.0 second

This means:

CARLA:
15 simulation updates per second

MAPPO:
approximately 1 tactical decision per second

Between MAPPO decisions:

the previous tactical action remains active.

Example:

t = 0.0
MAPPO → DECELERATE

t = 0.067
keep DECELERATE

t = 0.134
keep DECELERATE

...

t = 1.0
new MAPPO decision

This action persistence is REQUIRED.

Make the interval configurable.

============================================================
6. ACTION HYSTERESIS
============================================================

Implement action stability.

Do not allow insignificant changes in headway to cause immediate:

ACCELERATE ↔ DECELERATE

switching.

Use configurable hysteresis/deadband where appropriate.

Example:

desired headway = 20 m
headway deadband = 2 m

headway > 22 m
→ acceleration may be selected

18 m <= headway <= 22 m
→ CRUISE

headway < 18 m
→ deceleration may be selected

These values are configuration parameters.

Do not hard-code them throughout the code.

The MAPPO policy still learns the behavior.

The hysteresis exists to prevent unstable rapid tactical switching.

7. LANE CHANGE MUST BE A STATE MACHINE
============================================================

Do NOT treat lane changes as ordinary frame-by-frame commands.

The system must never randomly change lanes.
